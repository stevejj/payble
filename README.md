# 지갑 없는 날 (Walletless)

> 지갑이 없어도, 지금 이 자리에서 낼 수 있는 수단을 3초 안에 꺼내주는 앱

기획 메모(2026-09-08)의 **1차 MVP 범위**를 그대로 구현한 iOS 앱입니다.
1차 버전이 답해야 하는 질문은 하나입니다 — **"이 앱이 카카오페이 켜는 것보다 빠른가."**
그래서 앱 안에 그 숫자를 재는 계측이 들어 있습니다(설정 → 속도).

## 무엇이 들어 있나

| 기획서 1차 항목 | 구현 |
|---|---|
| 멤버십·포인트 바코드 저장 및 전체화면 표시 | `BarcodeStageView` — 검은 배경, 흰 카드, **밝기 자동 최대**, 자동 잠금 해제 |
| 페이 앱 딥링크 3~4개 | 카카오페이 · 네이버페이 · 현대카드 · 페이코 (`PayAppCatalog`) |
| 홈 위젯 — 탭 한 번에 바코드까지 | `QuickAccessWidget` (small/medium) + `LockScreenWidget` (잠금화면) |
| (추가) 탭 0회 경로 | App Intents — 뒷면 탭 · 액션 버튼 · 시리 · Spotlight · 제어 센터 |
| (추가) 지갑 없는 날 기록 | `DayLog` — 연속 일수 · 달력 · 최장 기록 |
| (추가) 카드별 사용처 | `PlaceCategory` — 언제 꺼내야 하는지가 카드에 적힌다 |
| 수동 순서 지정 | `ReorderView`. 맨 위 카드가 앱을 열자마자 보이는 카드 |
| 계정·로그인 없음 | 데이터는 App Group 컨테이너의 JSON 파일 하나. 서버로 나가는 통신이 **없음** |

의도적으로 뺀 것도 기획서 그대로입니다 — 위치 기반 자동 판단, 모바일 신분증, 로그인, 나가기 전 체크.
자동 정렬이 들어올 자리는 `RankingEngine`에 주석으로 표시해 두었습니다.

## 탭 0회 경로

위젯 탭 1회보다 빠른 길이 iOS에 있습니다. 앱이 App Intents로 **"바코드 열기"를 시스템 동작으로 등록**해 두기 때문에,
사용자는 그 동작을 아무 데나 붙이기만 하면 됩니다. 앱 안 **설정 > 탭 없이 열기**에 방법이 정리되어 있습니다.

| 경로 | 탭 | 비고 |
|---|---|---|
| 뒷면 두 번 탭 | 0 | 주머니에서 꺼내면서 이미 열려 있다. 가장 빠르다 |
| 액션 버튼 | 0 | 아이폰 15 Pro 이상 |
| "시리야, 지갑 없는 날 바코드" | 0 | 손이 하나만 비어 있을 때 |
| 제어 센터 | 1 | iOS 18+. 잠금 상태에서도 |
| Spotlight | 1 | 설정 불필요 |
| 홈 위젯 | 1 | |

`SpeedMetrics`가 이 경로들을 각각 따로 잽니다. 탭 없이 도달하는 경로는 탭 수를 0으로 기록합니다.

### 카드를 몰라도 여는 링크

`walletless://barcode/top`은 **맨 앞 카드**를 엽니다. 링크를 만드는 쪽(제어 센터, 위젯)이
어떤 카드가 있는지 알 필요가 없어서, **App Group 없이도 동작합니다.**
무료 Apple ID로 테스트할 때 위젯이 카드 이름은 못 띄워도 "바코드 열기" 버튼으로는 동작하는 이유입니다.

## 지갑 없는 날 기록

기획서에서 프레임을 **"지갑을 놓고 나왔다(사고) → 지갑을 일부러 안 든다(선택)"** 로 바꾼 것이
이 앱의 가장 중요한 판단인데, 정작 앱 어디에도 그 프레임이 보이지 않았습니다.

그래서 카드를 꺼내 쓴 날을 세어 홈 제목을 **"지갑 없이 27일째"** 로 바꿉니다.
제목을 누르면 이번 달 달력, 현재 연속, 최장 연속, 전체 일수가 나옵니다.

- 하루에 한 번만 기록되고, 그날 처음 쓴 순간에만 홈에 짧은 배너가 뜹니다.
- 배너는 **바코드를 닫은 뒤에** 뜹니다. 계산대 앞에서 방해하지 않기 위해서입니다.
- 연속 판정은 오늘 아직 안 썼어도 어제까지 이어졌다면 살아 있는 것으로 봅니다.
- 기록도 기기 안에만 남습니다. 서버로 나가지 않습니다.

경쟁 앱이 속도는 따라 할 수 있어도 사용자가 쌓아온 기록은 가져갈 수 없습니다.
기획서가 말한 **잔존 이유**가 여기에 해당합니다.

## 카드에 사용처 적기

바코드를 등록해두고도 **언제 꺼내야 할지 몰라서 못 쓰는** 경우가 많습니다.
그래서 카드마다 사용처를 붙이고, 그것이 카드 본문에 그대로 보이게 했습니다.

중요한 것은 **브랜드가 아니라 장소의 종류만 다룬다**는 점입니다.
어떤 매장이 어떤 포인트와 제휴했는지는 앱이 알 수 없고, 제휴는 수시로 바뀝니다.
틀린 정보는 정보 없음보다 나쁩니다 — 계산대에서 "여기 적립돼요"가 틀리면 그걸로 끝입니다.
그래서 **앱은 추측하지 않고 사용자가 고릅니다.**

온보딩 1단계에서 고른 장소가 그대로 카드 태그로 이어집니다.
(이전에는 그 답이 이름 추천에만 쓰이고 버려졌습니다.)

### 같은 장소 카드는 붙여서 보여준다

편의점 카드가 1번·5번·8번에 흩어져 있으면 계산대 앞에서 세 번을 찾아 헤맵니다.
그래서 같은 장소 태그를 가진 카드가 홈에서 **연달아** 나옵니다.

순서를 새로 만들지 않고 **사용자 순서에서 파생**시킵니다 —
장소 묶음의 순서는 그 장소의 첫 카드가 사용자 순서에서 나온 자리이고,
묶음 안의 순서는 사용자 순서 그대로입니다.
그래서 **맨 앞 카드는 절대 바뀌지 않습니다.** 탭 0회 경로가 여는 것이 그 카드입니다.
이미 묶인 목록에 다시 적용해도 결과가 같습니다(멱등).

고르게 만드는 화면은 만들지 않았습니다. 장소를 눌러 목록에서 고르는 방식은
탭을 늘리고, 계산대 앞에서 고르게 만들면 실패한다는 전제를 깨뜨립니다.
`설정 → 순서 정하기`에서 끌 수 있습니다.

### 2차로 미룬 것 — 지금 여기 판별

앱을 열 때 위치를 한 번만 보고 "지금 있는 곳이 편의점인지 카페인지"를 판별해
해당 태그의 카드를 앞에 올리는 것. **브랜드까지 알 필요가 없다는 게 핵심**이라,
제휴 데이터 없이도 동작합니다. 여기서 맞춰볼 대상이 바로 `PlaceCategory`입니다.

다만 기획서의 경고대로 자동 판단은 틀리면 그냥 느린 앱이 됩니다.
그래서 순서를 갈아엎기 전에 **배지만 붙이는 방식부터** 실기기에서 확인할 예정입니다.

## 설계에서 지킨 것

- **홈은 목록이 아니라 카드 한 장.** 애플 월렛처럼 겹쳐 쌓아서, 위아래로 밀면 다음 카드가 올라오고 끝에서 처음으로 이어집니다(1 → 2 → 3 → 1). 뒤 카드는 더 있다는 사실만 알려주는 정도로 고개를 내밉니다. 계산대 앞에서 목록을 훑게 만들면 실패입니다.
- **탭 횟수를 잰다.** 위젯 탭(1회) → 바코드가 목표 경로입니다. 평균 탭이 2회를 넘으면 설정 화면이 경고를 띄웁니다.
- **바코드는 보간 없이 그린다.** 늘릴 때 픽셀을 뭉개면 스캐너가 못 읽습니다.
- **온보딩은 3단계, 전부 건너뛰기 가능.** 이탈이 가장 많은 구간입니다.

## 바코드 렌더링

CoreImage에는 Code128·QR 생성기만 있고 국내 멤버십에서 가장 흔한 **EAN-13이 없습니다.**
그래서 `EANEncoder`에 EAN-13 / EAN-8 / UPC-A 인코더를 직접 넣었습니다.
L·G·R 패턴 표와 체크디지트 규칙은 알려진 유효 바코드로 검증했습니다(`5901234123457`, `4006381333931`, `96385074`, `036000291452`).
카드 뒷면 숫자에서 체크디지트가 빠져 있으면 자동으로 계산해 붙입니다.

## 아직 확인되지 않은 것 — 페이 앱 URL scheme

각 페이 앱의 URL scheme은 **공식 문서가 없고 앱 업데이트로 조용히 바뀝니다.**
그래서 코드는 어떤 scheme도 "된다"고 가정하지 않습니다.

- `PayAppCatalog`에 앱마다 후보 scheme을 여러 개 둡니다.
- 실기기에서 `canOpenURL`로 확인한 뒤, **실제로 열리는 것만** 골라 기억합니다.
- 설정 → **딥링크 진단**에서 어떤 후보가 살아 있는지 직접 확인할 수 있습니다.
- 하나도 안 열리면 App Store 검색으로 보냅니다. (존재하지 않는 앱 ID를 지어내지 않기 위해 검색 링크를 씁니다)

**실기기에서 이 화면을 한 번 열어보는 것이 첫 할 일입니다.** 초록불이 켜진 scheme만 실제로 동작합니다.

## 빌드

macOS + Xcode 15 이상, iOS 17 이상 타겟입니다.

```bash
brew install xcodegen   # 처음 한 번만
make open               # project.yml → Walletless.xcodeproj 생성 후 열기
```

맥북에 아무것도 깔려 있지 않다면 **[docs/mac-setup.md](docs/mac-setup.md)** 를 따라가면 됩니다.

Xcode에서 두 가지만 본인 것으로 바꾸면 바로 실행됩니다.

1. **App Group** — `Sources/Shared/AppGroup.swift`의 `identifier`, 그리고 두 entitlements 파일
   (`Sources/App/Resources/Walletless.entitlements`, `Sources/Widget/WalletlessWidget.entitlements`).
   세 곳이 같아야 위젯이 카드를 읽습니다. 안 맞으면 설정 화면이 경고합니다.
2. **Bundle ID / 팀** — `project.yml`의 `PRODUCT_BUNDLE_IDENTIFIER`와 `DEVELOPMENT_TEAM`.

바코드 스캔과 밝기 조절은 시뮬레이터에서 확인할 수 없습니다. 실기기로 테스트하세요.

### 무료 Apple ID로 실기기에 올리기

**Apple Developer Program($99) 없이도** 본인 아이폰에 설치해 실행할 수 있습니다(무료 프로비저닝).
다만 무료 개인 팀은 **App Groups capability를 지원하지 않아** entitlement가 남아 있으면
Xcode가 서명 단계에서 거부합니다. 아래 명령이 그 설정을 대신 해줍니다.

```bash
make free PREFIX=com.본인도메인.walletless
# 팀 ID를 알고 있다면 (Xcode > Settings > Accounts)
make free PREFIX=com.본인도메인.walletless TEAM=ABCD123456
```

하는 일은 세 가지뿐입니다 — 두 entitlements 파일을 비우고, 번들 ID를 넘긴 접두사로 바꾸고,
프로젝트를 다시 생성합니다. 그다음 Xcode에서 두 타겟의 Team을 본인 Personal Team으로 고르고,
아이폰을 연결해 Run 한 뒤, 아이폰 **설정 > 일반 > VPN 및 기기 관리**에서 인증서를 신뢰하면 됩니다.

| 무료 계정으로 확인 가능 | 확인 불가 |
|---|---|
| 앱 실행, 카드 등록, **카메라 바코드 스캔** | **위젯에 카드 이름 표시** (App Groups 필요) |
| 전체화면 바코드 + 밝기 최대 → 매장 스캐너 인식 | 위젯 · 잠금화면 경로의 속도 측정 |
| 딥링크 진단 (살아 있는 URL scheme 확인) | TestFlight 배포 |
| **탭 0회 경로 전부** (뒷면 탭·시리·제어 센터) | |
| 위젯의 "바코드 열기" 버튼 (이름 없이) | |

앱 본체는 App Group이 없어도 **정상 동작합니다.** `WalletStorage`가 공유 컨테이너를 못 찾으면
앱 내부 저장소로 넘어가고, 설정 화면이 그 상태를 경고로 알려줍니다.
위젯만 데이터를 읽지 못해 빈 상태로 보이는데, 이는 무료 계정의 제약이지 버그가 아닙니다.

무료 설치는 **7일 후 만료**되며, 맥에 다시 연결해 Run 하면 갱신됩니다.
유료 프로그램에 가입한 뒤에는 `make paid`로 App Groups 설정을 되돌리면 위젯이 정상 동작합니다.

이 앱의 핵심 주장인 **"위젯 탭 한 번 → 바코드"** 경로는 유료 계정이 있어야 검증됩니다.
반대로 **바코드가 매장에서 실제로 읽히는지, 딥링크가 열리는지는 무료로 오늘 확인할 수 있습니다.**
그 둘이 먼저이므로 무료로 시작해도 충분합니다.

### 맥이 없다면

`.github/workflows/ios-build.yml`이 PR마다 macOS 러너에서 `xcodegen` + `xcodebuild`를 돌립니다.
컴파일 오류는 PR의 체크 결과로 확인할 수 있습니다 — 맥 없이도 코드가 빌드되는지는 알 수 있습니다.
다만 **실기기 설치는 별개**입니다. 아이폰에 올리려면 Apple Developer Program 가입 후
App Store Connect API 키로 CI에서 서명·업로드해 TestFlight로 받는 경로가 필요합니다.

public 저장소라 macOS 러너는 무료입니다. 빌드 로그에서 오류·경고만 뽑아
Actions의 요약 화면에 남기므로 폰에서도 읽을 수 있습니다.

## 구조

```
Sources/
  Shared/        앱과 위젯이 함께 쓰는 것 (모델 · 저장 · 바코드 인코딩 · 딥링크)
  App/           앱 본체 (화면 · 라우팅 · 속도 계측 · 밝기 제어)
  App/Intents/   시리 · 단축어 · 제어 센터가 부르는 동작
  Widget/        홈 위젯 + 잠금화면 위젯 + 제어 센터 컨트롤
Scripts/
  free-signing.sh  무료 Apple ID로 실기기에 올리기 위한 설정 (make free)
  make-icon.py     앱 아이콘 생성기 (디자인 도구 없이 다시 만들 수 있게)
```

## 아이콘

바코드 막대 다섯 개. 맨 앞 하나만 액센트 색인데, 이 앱이 하는 일이
**맨 앞 카드를 꺼내주는 것**이기 때문입니다.

홈 화면에서 60pt로 줄어들어도 읽히도록 막대를 적게, 굵게 잡았습니다.
`Scripts/make-icon.py`가 외부 라이브러리 없이 PNG를 직접 만듭니다.

```bash
python3 Scripts/make-icon.py          # 시안 3종을 build/icons/ 에 생성
python3 Scripts/make-icon.py ink      # 고른 시안을 에셋 카탈로그에 설치
```

시안은 `ink`(짙은 배경) · `paper`(밝은 배경) · `blue`(파란 배경) 세 가지이고
현재 `ink`가 적용되어 있습니다. 색이나 막대 배치는 스크립트 상단에서 바꿉니다.

- [ ] **본인이 2주간 지갑 없이 살기** — 가장 빠른 검증. 가정 1·2를 동시에 확인하고, 진짜 병목이 결제인지 신분증인지 드러납니다.
- [ ] 인터뷰 10명 — 과거 행동만 질문. "이런 앱 쓸래?"는 데이터가 아닙니다.
